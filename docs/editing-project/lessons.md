# Lessons — Playlist editing project

Read this at the start of every session on this project. One short entry per lesson: what, and why it mattered.

## Carried over from earlier Dawesome sessions

- **Do not use `git stash` to get a "before" baseline.** Compare against `git show HEAD:<file>` instead. Why: on 2026-11-08 a stash/pop round trip left a stale engine binary, and the app reported commands as "not found" until a clean rebuild.
- **If engine commands come back "not found" although they are registered in `engine/src/main.rs`,** run `cargo clean -p app && cargo build --no-default-features` in `engine/`, then restart `tauri dev`. Why: `tauri dev` builds with `--no-default-features`, which cargo caches separately from a plain `cargo build`.
- **Tauri is held at 2.11.x because the local compiler is rustc 1.86.** The JS and Rust Tauri minor versions must match. Why: Tauri 2.12 and later need a newer compiler, and the Tauri CLI refuses to build on a mismatch. Any new crate for this project has to build on 1.86 too.

## From this project

- **Check an exploration agent's surprising claims in the source before writing them down.** Worked on 2026-11-10: the "playback is 16-bit" and "pitch only relabels the sample rate" claims were confirmed in rodio's own source before they went into the codebase map. Why: design questions built on a wrong fact waste a whole question round.
- **Ask design questions as a questionnaire in the chat, not as a file to tick.** On 2026-11-10 the user asked for this after seeing the 165-question file. Record every answer in `docs/editing-project/` straight away, quoting the user's own words where they wrote any. Why: answering in chat is faster for them, and asking live lets later questions adapt to earlier answers.
- **Commits for this project: I commit at the end of each milestone, with one short lowercase line in the user's own style (for example "caching waveforms") and no trailer lines.** The user allowed commits "for just this one project" on 2026-11-10. Never stage `docs/todo.md`. Why: the user normally commits everything themselves.
- **When an answer changes what a later question means, rewrite the later question before asking it.** Worked on 2026-11-10: after "tape-style stretch" the library and render questions were dropped and the remaining stretch questions were reworded around the Pitch setting. Why: asking stale questions wastes the user's time and produces answers that contradict each other.
- **When the user hands over autonomy, keep a running decisions log.** On 2026-11-10 the user said to work overnight, assume my own recommendation for new questions, and report the decisions in the morning. Every such decision goes in `06-decisions-log.md` as it is made, with the alternative. Why: they want to be able to revisit each one, and they answered the last follow-ups (F22 onward) without reading them.
- **Run engine tests from `engine/`.** Why: the tests open samples by paths like `assets/...`, relative to the working directory.
- **`pnpm exec tsc --noEmit` is not a real typecheck here.** It stops at the missing `@testing-library/jest-dom` types and reports nothing else. Run `pnpm exec tsc --noEmit --types jest` as well: its baseline is 3 errors, all in code this project does not touch (`src/util/debounce.ts`, two in the unused `src/views/sample-details/`). Found on 2026-11-10 by the agent doing the M4 types. Why: type errors in new code, spec files included, were invisible to the stated gate.
- **Subagents run on the model for their tier: `sonnet` for well-specified implementation, `opus` for verifiers; only the main session uses Fable.** The user asked for this on 2026-11-10 after usage limits stopped the session twice. Set `model` on every agent; an agent that inherits the main model is replaced, not resumed. Why: a verifier that inherited Fable died on the limit.
- **Don't edit source while a subagent is running tests in the same tree.** Give it its checks to run first, tell it which files are mid-change, or wait. Draft new files in the scratchpad meanwhile. Why: its gate numbers are only meaningful against a tree that compiles.
- **Nanoseconds are not a fine enough unit to be careless with.** `Duration::div_f32` and `as_secs_f32` keep about seven digits, which is tens of microseconds on a five-minute position; a frame at 48 kHz is 20.8 µs. For anything that decides which frame a sound lands on, use `f64` and derive related times from one shared value (M4: the halves of a cut share an origin). Why: two values that are "the same time" computed two ways can round to different frames.
- **Check every factual claim in a brief before handing it to an agent.** On 2026-11-10 my brief for the Playlist tray said the Snap key "brings the snap-value drop-down with it". It does not; the agent did what the brief said, the drop-down stayed in the topbar, and only the verifier caught it. Why: an agent follows the brief, and a review that trusts the brief does not catch the brief's own mistakes.
- **When a change lets something keep its id but change what it is, look for caches keyed by that id.** Deep copy keeps a clip's id and gives it a new file; the canvas kept waveforms by clip id and would have drawn the old one. Found in review, not by a test. Why: "ids are never reused" was written down as an assumption in the canvas code, and it was no longer true.
- **A verifier that re-derives the arithmetic finds what tests at friendly numbers miss.** The Opus verifiers found fades off by up to 50 steps after a cut (tests had no fades), a join refused at 90 bpm (tests ran at 120), and a crash on a file name with a Kelvin sign. Ask verifiers to try awkward tempos, pitches, names and positions, and give them a scratch folder for scripts. Why: tests written by the author share the author's blind spots.
- **In Rust tests, a lock taken in an argument expression is held for the whole statement.** `f(&[state.x.lock().unwrap().field])` deadlocks if `f` takes the same lock. Bind the value first. Why: this hung a test run for two minutes on 2026-11-10.
- **Give a long test command a time limit.** `timeout 115 cargo test …` returns control when a test hangs; without it the run goes to the background and the next command builds on nothing.
